# Scopify 移动端页面规格

> 产品基线：独立 Flutter App，与 Web/Electron 共用后端，但不共享前端、播放状态或发布周期。
> 首发平台：Android。iOS 在 Android 核心体验稳定后跟进。
> 首轮目标：**先把全部页面的低保真布局、导航关系和状态槽位搭出来，不追求一次完成视觉稿。**

Web 能力与接口映射见 [web-capabilities.md](./web-capabilities.md)，视觉语言与 Flutter 映射见 [web-design-language.md](./web-design-language.md)，实施与目录约束见 [project-plan.md](./project-plan.md)，可浏览线稿见 [wireframes/mobile-wireframe-prototype.html](./wireframes/mobile-wireframe-prototype.html)。

## 1. V1 产品边界

- 独立移动客户端，不是 Web 遥控器，也不使用 WebView 承载主页面。
- 底部一级导航固定三个：**首页 / 搜索 / 我的**。
- 游客可使用首页、搜索、公开详情、公开播放和读取歌曲评论。
- “我的”与账号写操作要求登录；登录只有网易云二维码。
- 播放是纯在线流媒体，不提供离线下载库。
- V1 包含 Android 后台播放、通知栏、锁屏和媒体按键控制。
- V1 使用原生 Flutter 完整播放页与同步歌词，并采用 Folia 式“原文主行 + 紧贴翻译”的歌词排版；Folia 全套视觉效果后置。
- 页面要完整预留加载、空、失败、登录门槛和内容状态，不能只画“成功有数据”。

## 3. 全局壳层

### SHELL-01 App Shell

固定元素：

- 顶部安全区由每个一级页拥有，不增加桌面式全局侧边栏。
- 一级页左上角固定为 App Drawer 汉堡入口；App Drawer 是覆盖层，不是第四个一级页面或常驻侧栏。
- 页面内容区独立保留滚动位置。
- 迷你播放器与底部导航是 App Shell 内两个独立组件：有当前歌曲时，迷你播放器以独立浮层显示在导航上方并保留间距；没有歌曲时只收起迷你播放器，底部导航的结构和位置不变。
- 底部导航只显示首页、搜索、我的，切换一级页不重建播放队列。
- App 根部提供唯一的全局 Toast Host，固定在安全区顶部并覆盖当前 route、播放器和 sheet；任何 feature 只发出通知意图，不能各自挂一份 Toast。
- 歌单、歌手、专辑、DJ Radio 和 Voice List 等普通内容详情保留三项底部导航，并高亮进入来源；不能因为进入详情而让用户失去一级位置感。
- 二维码登录、完整播放页、歌词、队列和评论会以全屏层或模态覆盖 App Shell，明确隐藏底部导航，关闭后回到原来源。
- 迷你播放器至少显示封面、标题、歌手、播放/暂停；点击其余区域打开完整播放页。
- 键盘弹出时，搜索输入与评论输入必须可见；底部导航可按平台惯例暂时避让或隐藏。

### SHELL-02 App Drawer

App Drawer 是 App Shell 的全局低频工具入口，登录态与游客态共用同一结构：

- 只在首页、搜索、我的三个一级根页面挂载；左上角汉堡按钮始终可用。
- 一级根页面允许从左边缘拖入，但只使用平台默认的窄识别区。普通详情页保留 Android 系统返回手势，不注册 Drawer 边缘拖拽。
- Profile、歌单、歌手等普通详情只显示返回和页面自身的更多操作，不显示 Drawer 汉堡按钮。登录、完整播放器、队列、评论等沉浸层，以及后端不可达等阻断页同样不挂载 Drawer。
- 登录态账号头部显示头像、昵称和签名，点击进入自己的 PROFILE-01；游客头部显示扫码登录入口。
- 网易乐签使用独立卡片；游客与未加载状态保留卡片轮廓并展示明确状态，不隐藏入口。
- 听歌识曲对游客和登录用户都可用；它只要求麦克风权限，不成为账号能力。
- 最近播放与 My 快捷入口进入同一个 RECENT-01；当前线稿阶段允许入口重复，整体评审后再决定是否精简。
- 睡眠定时与检查更新对游客同样可用；设置始终显示。退出账号只在登录态出现。
- Drawer 内动作若打开 Modal，必须先完成 Drawer 收起，再显示 Modal；关闭 Modal 后回到原页面，不自动重开 Drawer。页面跳转同样先关闭 Drawer，再 push 对应 typed route。
- 后端连接正常时不在 Drawer 显示技术状态；连接完全不可用时直接进入 SYS-01 阻断状态，用户只能重试或进入网络设置。

### SHELL-03 全局登录门槛

登录门槛分两种：

1. 进入“我的”：留在 My Tab 内展示登录说明和主按钮，点击后打开全屏二维码登录。
2. 游客触发写操作：保留当前页面，弹出简短原因说明；登录成功后返回原位置，并由用户重新确认写操作，避免自动重复提交。

登录取消、二维码过期和网络错误都不能清空游客已有的播放队列。

## 5. 启动与登录

### SYS-01 Launch Gate

职责：

- 读取默认或用户配置的 Mobile Backend Endpoint。
- 执行传输安全校验；公共 HTTP 直接阻止继续，私网/localhost HTTP 显示明确标识后允许。
- 恢复加密保存的会话凭据并调用 `/login/status`。
- 会话无效时进入游客 Shell，而不是停在强制登录页。
- 后端不可达时提供“重试 / 打开网络设置 / 继续查看已有本地壳层”三个方向；首轮线稿只需保留位置。

首屏不能长时间只显示品牌图。超过短暂启动阶段后必须暴露当前动作或错误。

### AUTH-01 二维码登录

布局：

- 顶部：关闭、标题“扫码登录”。
- 中部：后端返回的方形 Base64 二维码；加载时用等尺寸占位，避免页面跳动。
- 二维码主体在可用区域中视觉居中，不能全部堆在页面上半部。
- 二维码轮询状态与 Web 保持一致，固定显示在二维码下方，不使用倒计时或底部 toast。等待态文案为“打开 App 扫一扫登录 / 使用 网易云音乐 App 扫码”。
- `scanned` 时直接在二维码上覆盖半透明遮罩，显示“请在手机上确认”；`expired` 时覆盖较深遮罩和“刷新二维码”动作。刷新只出现在过期/网络失败状态，不能在等待态额外放一个永久刷新按钮。
- 截图、保存/分享图片是独立系统能力入口（若平台实现），不与扫码状态混在一起；同时明确用户也可直接截图。这个说明固定在登录安全区最底部，使用系统弱化色和淡色圆形 `!` 图标，不做醒目的告警框。
- 辅助说明：本 App 只提供二维码登录，不展示手机号、密码或短信标签页。

状态机与 Web `QrLogin` 对齐，使用同一个 key 顺序轮询；每次请求处理完后等待约 3 秒再开始下一轮：

| Web 结果 | 移动状态 | 二维码区域 | 二维码下方状态 |
| --- | --- | --- | --- |
| 获取 key / 生成图片中 | `loading` | 等尺寸生成占位 | 正在加载二维码… |
| `801` | `waiting` | 正常二维码 | 打开 App 扫一扫登录；使用 网易云音乐 App 扫码 |
| `802` | `scanned` | 半透明遮罩 | 已扫码，请在手机上确认 |
| `800` | `expired` | 深色遮罩 + 刷新二维码 | 二维码已过期 |
| `803` | `success` | 保留二维码直至离开 | 授权登录成功！随后保存凭据、读取用户信息并返回来源 |
| 轮询/后续账户校验失败 | `expired` 视觉变体 | 深色遮罩 + 刷新二维码 | 网络请求失败或登录状态异常 |

关闭、刷新、过期、网络错误和离开页面都必须取消旧 key 的轮询；成功前的任何旧结果都不能覆盖新二维码流程。游客已有的播放队列和来源页面保持不变。

## 6. 一级页面

### HOME-01 首页

视觉方向：沿用 Web 的时段渐变和区块顺序，但改成单手滚动布局；卡片密度由手机宽度决定。

从上到下：

1. 时段欢迎语；登录后显示昵称。
2. 每日推荐大入口 + 最多若干快捷歌单，首屏能看见可播放内容。
3. Featured Activities 横向轮播。
4. Recommended Voice Feed 横向或紧凑列表。
5. 局部网络错误条与重试。
6. 为你推荐歌单的横向卡片组。
7. 推荐歌手的圆形卡片组。

动作：打开详情、直接播放歌单/声音、滑动轮播、重试单个失败区域。游客没有账号推荐时保留公开区块，不出现空白大洞。

### SEARCH-01 搜索发现

视觉方向：采用已确认的 Spotify 风格。

- 大标题“搜索”。
- 高对比度大搜索框，整个区域可点，支持清除和系统键盘搜索动作。
- “浏览全部”双列分类卡：每日推荐、为你推荐、热门歌手、新碟、播客、声音。卡片只是现有能力的快捷入口，不声明新的后端分类体系。
- 有当前歌曲时保留迷你播放器和三项底部导航。

首轮线稿不需要真实搜索历史；后续若加入历史，必须可由用户清除。

### SEARCH-02 搜索结果

- 结果页顶部使用两层搜索头：第一行只承担返回与“搜索”上下文，第二行是满宽、可清除的查询框；不能把返回、输入和清除动作硬塞进一行 App Bar。
- 搜索框保持在顶部，输入变化使用防抖并取消旧请求。
- 横向滚动筛选固定七项：全部、歌曲、歌手、歌单、专辑、播客、声音。
- “全部”显示最佳匹配和各类摘要；其他筛选显示单类分页。
- 歌曲/声音使用行列表；歌手用圆形封面；歌单/专辑/播客使用卡片或紧凑列表。
- 下一页失败保留已有结果，只在尾部展示重试。
- 清空关键词返回 SEARCH-01，不保留空结果壳。

### MY-00 我的游客态

保留与登录态相同的页面轮廓，避免点击 Tab 后完全换风格：

- 占位头像与“登录后同步你的音乐库”。
- 主按钮“使用网易云音乐扫码登录”。
- 仍可进入设置，尤其是网络地址与关于。
- 音乐/播客/收藏内容区使用登录门槛说明，不发账号接口请求。

### MY-01 我的 / 音乐

音乐、播客、收藏三页统一采用已确认的首个布局：沉浸背景、居中且留白充足的个人资料头部、快捷入口、玻璃质感内容面板和内部三 Tab。

个人头部：头像、昵称、简短签名、VIP 本地徽标、关注/粉丝/喜欢统计。快捷入口固定为：最近、我喜欢、创建歌单、设置。

这套资料头和快捷入口不能因内部 Tab 切到播客或收藏而缩成简略版本。整个 My 内容区为纵向可滚动区域：首屏允许资料头占据更多空间，向下滑动时资料头、快捷入口和各 Tab 内容一起向上移动，迷你播放器与底部导航保持独立固定。

My Section Switcher：**音乐 / 播客 / 收藏**。音乐内的信息层级：

- 固定首项“我喜欢的音乐”。
- 子筛选“最近 / 创建 / 收藏歌单”。
- 每行显示封面、名称、类型/歌曲数/创建者和更多按钮。
- 创建歌单使用底部表单；首轮线稿只画入口与表单结构，不执行写操作。

收藏歌单属于这里，不能放到 MY-03。

### MY-02 我的 / 播客

内部子筛选正好三项：

- **订阅**：已订阅 Voice List；可切换紧凑列表/卡片属于后续视觉细化，不增加信息架构。
- **创建**：用户已经创建的 Voice List。这里不是“新建 Voice List”动作，当前后端适配没有创建写接口。
- **喜欢的声音**：可直接播放，也可打开文字稿。

订阅区下方可展示播客推荐。旧 DJ Radio 与 Voice List 在数据模型和详情路由中保持区分，界面文案可以统一使用用户熟悉的“播客”。

### MY-03 我的 / 收藏

只包含：

- 关注的歌手。
- 收藏的专辑。

可用“歌手 / 专辑”二级筛选或连续两个区块。歌手头像为圆形、专辑封面为方形。没有歌单、喜欢歌曲、播客或声音。

### RECENT-01 最近播放

App Drawer 与 My 的“最近”只提供两个入口，共用同一个页面、route 和数据状态：

- 首版只展示最近歌曲，直接复用 PLAYLIST-01 的页面骨架、主播放操作、搜索框和曲目列表，不再创建“歌曲 / 歌单”双 Tab 布局。
- 列表显示序号、封面、标题、歌手、最近播放时间和时长；点击歌曲使用同一个 Playback Module 播放。
- “全部播放”和随机播放只构建本次已加载的最近歌曲队列，不创建或修改服务端歌单。
- 最近歌单与最近专辑保留为后续扩展；加入前重新评审信息密度，不提前占据首版布局。
- 这是普通内容详情，保留迷你播放器和来源一级 Tab；顶部只有返回与页面更多操作，不提供 Drawer。

## 7. 内容详情页

### 共通 Action Bar

详情页的操作区以 Web 端的播放控制条为视觉基线，而不是把动作散放在标题下方：

- 最左侧永远是醒目的 Spotify 绿圆形主播放按钮；播放、暂停切换仍使用同一位置。
- 有随机播放能力的歌单和专辑，在主播放右侧紧跟绿色随机图标与状态点。
- 关注、订阅等状态动作使用紧凑描边胶囊；收藏使用弱化的心形图标；更多操作保持最弱的中性色图标。
- V1 没有离线下载，因此不复刻 Web 的下载图标，避免出现没有响应的假操作。
- 操作条与曲目搜索、筛选等列表工具分开，保证主播放始终是详情首要动作。

### PLAYLIST-01 歌单、我喜欢与每日推荐

通用结构：

- 顶部返回/更多。
- 封面、名称、创建者、描述、标签、歌曲数/收藏数。
- 主播放按钮、随机、收藏或编辑入口、列表内搜索。
- 曲目列表：序号、标题、歌手/专辑、时长、喜欢状态、更多。
- 底部迷你播放器与安全区。

变体：

- 自己的歌单：编辑资料、封面、标签，删除，加删歌曲。
- 他人的歌单：展示收藏状态；切换收藏在集成前需复核 Web 活跃入口。
- 我喜欢：不显示歌单编辑，喜欢切换直接更新列表。
- 每日推荐：支持“不感兴趣”和历史日期入口；无权限时显示真实后端提示。

V1 不包含离线下载、歌单评论和曲目持久化重排。

### ARTIST-01 歌手详情

- 大图/头像、名称、粉丝数、简介。
- 播放热门歌曲、关注/取消关注。
- 热门歌曲摘要与“全部”。
- 专辑横向卡片，进入 ALBUM-01。
- MV 不在 V1；不能展示无响应的 MV Tab。

### ALBUM-01 专辑详情

- 封面、名称、歌手、发行时间、类型、公司和描述。
- 整张播放、随机、收藏/取消收藏。
- 只读曲目列表；点歌手进入 ARTIST-01。
- 游客可读和播放；收藏触发登录。

### AUDIO-01 DJ Radio / Voice List

共享视觉骨架，但数据类型不能混用：

- 封面、标题、主播/创建者、分类、简介和订阅状态。
- DJ Radio 显示 DJ Programs；Voice List 显示 Voices。
- 可用内容直接构建播放队列。
- Voice 有文字稿时提供入口；无文字稿显示明确空状态。

### PROFILE-01 / PROFILE-02 用户资料

PROFILE-01 参考网易云移动资料页的单列视觉层级，但内容严格对齐 Scopify Web 已有资料能力，不照搬聊天、笔记、共同关注或其他未确认入口：

- 顶部左侧为返回，右侧为该资料页自己的更多操作；不显示 Drawer 汉堡按钮，也不注册 Drawer 边缘拖拽。
- 资料区居中显示头像、昵称、签名、地区、星座、加入时间、本地 VIP 徽标、等级与听歌数；关注、粉丝和歌单统计保持紧凑。
- 自己与他人共用同一个 Profile 页面和 Layout。自己的资料显示“编辑资料”，内容区展示最近歌曲与最近歌单；他人资料显示“关注 / 已关注”，内容区展示公开歌单。
- 关注用户必须真实调用 `/follow?id=...&t=1|0`，不能复制 Web 当前仅在组件内切换文字的假状态。游客点击关注时打开二维码登录；请求失败回滚乐观状态并使用全局 Toast。
- Profile 属于普通详情，保留迷你播放器与来源一级 Tab。通过 App Drawer 进入时，返回后回到原一级页面和滚动位置。

PROFILE-02 是覆盖式编辑 Modal，与 PROFILE-01 共用已加载用户数据。它使用短表单编辑当前后端已支持的昵称、签名和性别；保存前做本地校验，保存失败保留输入且不自动退出。

### VIP-01 网易乐签

- App Drawer 使用账号卡片展示“今日未签 / 今日已签”、连续天数和本月累计。
- 游客点击卡片进入二维码登录。未签到用户点击后直接执行签到；签到成功显示结果 Modal。已签到用户不重复执行写操作，只读取并打开同一个 Modal。
- Modal 直接继承 Web `VipSignModal` 的信息层级：顶部日期；中部歌曲标题、歌手、祝福语与右侧封面；点状分隔线；底部本月累计与网易云音乐二维码引导。移动端只压缩比例，不改成普通歌曲结果卡，也不额外加入七日签到格。
- 封面右下角的播放按钮命令同一个 Playback Module；右上角关闭与点击遮罩均回到进入前页面。
- 打开 Modal 前先收起 Drawer；失败保留原页面并通过全局 Toast 提供重试，不创建独立 route。

### SLEEP-01 睡眠定时

- App Drawer 与完整播放器共用同一个覆盖式 Modal，不创建独立 route。
- 首版选项为：未开启、当前歌曲播放完后、15、30、45、60 分钟后停止。
- 计时由 Playback Module 持有，App 进入后台后继续；到期只停止播放，不关闭 App、不清空队列。
- 当前剩余时间在 Drawer 行与完整播放器入口保持一致；取消定时立即恢复“未开启”。

### MATCH-01 听歌识曲

- Drawer 收起后打开覆盖式 Modal，不创建独立 route；游客与登录用户使用同一流程。
- 首次使用时申请麦克风权限。拒绝后停留在 Modal 内解释原因；永久拒绝时提供系统权限设置入口；取消、关闭或 App 进入后台时立即停止采样并释放麦克风。
- 现有后端 `/audio/match` 不接收原始录音。客户端采集约 3 秒环境声音，在本地生成声纹，然后只提交 `duration` 与 `audioFP`；原始采样仅驻留内存，识别结束后销毁。
- 当前 Web Demo 使用 8 kHz 采样和 `ncm-afp` WASM `GenerateFP(Float32Array)`。Flutter 端的等价本地声纹实现仍属于技术验证项，在验证通过前不得把“上传录音给后端”当作替代方案写入生产设计。
- 成功时在同一 Modal 展示歌曲、歌手/专辑与匹配起始时间，允许直接交给 Playback Module 播放；无结果、网络失败与声纹生成失败分别给出重新识别，不混成同一种错误。

### UPDATE-01 检查更新

- Drawer 收起后打开覆盖式 Modal，不创建独立 route；检查期间不阻断浏览或当前播放。
- Android 首版以 GitHub Releases 的 latest release 和 Release Assets 为更新源，展示当前版本、最新版本、发布日期、Release Notes、APK 名称与大小。
- 有新版本时提供“下载 APK”和“查看发布页”。下载显示进度、取消与失败重试；完成后必须校验 Release Asset 提供的 SHA-256 digest，再交给 Android 系统安装器。
- 非 Play 分发需要用户允许该来源安装 APK；权限未开启时只引导进入系统设置，不伪装为下载失败。未来若进入 Google Play，再切换为 Play In-App Updates。
- 本轮只确认入口、Modal 与状态合同，实际更新下载和安装实现后置；设置“关于”页可复用同一个检查更新动作，不再创建第二套更新逻辑。

## 8. 播放层

### PLAYER-01 完整播放页

采用已确认的参考：沉浸式专辑背景、中央唱片与唱臂、下半部信息和控制。PLAYER-01 只有一个全屏 route；CD 与同步歌词是同一页面的**中心模式**，不是两页 Pager，也不是歌词 modal。

线稿总览将两个中心状态分别陈列为 `PLAYER-01A · CD 中心` 与 `PLAYER-01B · 同步歌词中心` 两张静态画面，不实现点按、滑动或模式切换交互；这只服务于评审，不改变运行时的单一 route 设计。

- 从迷你播放器、歌曲播放动作进入完整播放页时，默认显示 CD 中心模式。
- 轻点中央唱片切到同步歌词；再次轻点中心歌词区切回 CD。禁止左右滑动、横向 PageView、scroll-snap 和以歌词工具替代此主入口。
- 顶部栏、歌曲资料、进度、播放控制、工具与评论入口在两种模式间保持同一实例和同一位置；只替换中心区域内容。
- 切换中心模式不暂停播放、不重新请求音源、不创建嵌套 Navigator 或 sheet。开启“减少动态效果”时直接切换或使用极短淡化。
- 从播放器最底部的无文字评论手势把手向上滑动，直接进入 COMMENT-01；同时保留可聚焦的“查看评论”语义动作作为无手势等价入口。进度条、主控制和队列按钮不响应这条上滑手势。

结构：

- 顶部收起、来源歌单/队列标题、分享占位。
- 中心区域：CD 模式展示唱片/唱臂，歌词模式展示同步歌词；CD 是主视觉，播放时允许轻量旋转，低性能或“减少动态效果”时静止。
- 共享底部区域：歌名、歌手、关注按钮、喜欢数、评论数、可拖动进度、当前时间、总时长、当前音质、随机、上一首、播放/暂停、下一首与队列。它直接叠在沉浸背景上，只用渐变保障可读性，不能做成厚重的纯黑底栏、卡片或强分隔线。
- 工具：设备（可后置）、音效、定时关闭、音质、更多；不再额外摆放“歌词”工具。工具是低对比度图标层，不与中央唱片、歌词或主播放争夺视觉焦点。
- 最底部是独立评论手势把手，只保留短横视觉标识，不显示操作提示文字。

V1 必须保证控制可靠性高于动画。后台、锁屏和页面控制都操作同一个 device-local Playback Module。

### PLAYER-01 同步歌词中心模式

- 它只替换完整播放页的中心区域，不是卡片、小窗口、底部 sheet 或独立 route；顶部栏与共享底部控制保持原样。
- 当前行高亮、前后行弱化、自动滚动。歌词内容占据全部中心空间，不能被浮层边框、圆角或“背景播放器缩略图”挤压。
- 歌词直接继承完整播放器的沉浸背景；不能额外铺一块矩形背景、卡片或局部渐变。
- V1 固定采用 Folia 式原文 + 翻译双行：原文是主行，翻译紧贴在下方并弱化；有翻译即展示，无翻译时自然收拢为单行。首版不提供原文/翻译切换、罗马音或隐藏字幕模式。
- 轻点中心歌词区返回 CD；不提供左右滑动返回路径。
- 拖动歌词或点行跳转必须显示时间提示；如果 V1 不实现点行跳转，就不展示可点击反馈。
- 无歌词、纯音乐、加载失败和重试分别呈现。

### PLAYER-02 播放队列

使用底部抽屉或全屏 sheet：

- 当前播放高亮。
- 点击切歌、删除队列项、移到下一首。
- 随机/循环状态可见。
- 本地拖拽排序属于队列操作，不等同于服务器歌单曲目重排。

### COMMENT-01 歌曲评论

- 由 PLAYER-01 最底部的上滑手势槽直接进入；为辅助功能和鼠标/键盘提供等价的“查看评论”动作。
- 向下滑或使用返回动作回到完整播放页，并保留进入前的 CD / 歌词中心模式、播放进度和队列。
- 顶部歌曲摘要与评论总数。
- 热门评论区、普通评论区、20 条分页。
- 游客可读；底部输入区触发登录门槛。
- 登录后支持点赞、取消点赞、发布、回复、删除自己的评论。
- 回复时固定显示目标用户；取消回复后恢复普通发布。
- 分页失败不清空已有评论，写入失败不丢失输入文本。

### SETTINGS-00 设置索引

移动端采用系统列表层级，而不是把 Web 的横向 Tab 硬塞进窄屏：

| 分组 | 内容 |
| --- | --- |
| 通用 | 语言、外观/跟随系统、减少动态效果 |
| 播放 | 默认音质、蜂窝网络策略、定时关闭入口、后台播放说明 |

| 关于 | 版本、构建号、开源许可证、源代码、隐私说明 |

### SETTINGS-03 网络

后端地址使用完整 URL 输入比拆分 host/port 更适合移动端，但保存时归一化为统一 Endpoint 模型。页面必须显示：

- 当前解析出的协议、主机和端口。
- “测试连接”结果、延迟、后端版本或明确失败原因。
- “恢复默认”二次确认；入口固定为页面底部居中的 Spotify 风格绿色长圆角按钮，不与“测试连接”并列，并与底部安全区保留约 32 px 间距。

- localhost、回环和私有网段 HTTP 为“允许但不安全的本地连接”。
- 其他 HTTP 公共地址为阻止保存的错误。

本地调试 Android 模拟器访问宿主机时，具体地址由开发文档说明，不在产品 UI 中硬编码特殊逻辑。

## 10. 所有页面必须具备的状态

页面实现不能用一个 `isLoading` 覆盖所有情况。至少区分：

| 状态 | 表现要求 |
| --- | --- |
| 首次加载 | 没有可渲染缓存时，显示与最终页面形状一致的骨架 |
| 刷新中 | 保留旧内容并显示轻量进度 |
| 成功有内容 | 标准页面 |
| 成功空内容 | 解释为什么为空，并给出合理下一步 |
| 首次加载失败 | 页面级错误、重试和必要时网络设置入口 |
| 局部/分页失败 | 保留已有内容，在失败区域就地重试 |
| 写操作失败 | 撤销乐观更新，以 Toast 说明结果；评论输入等用户内容不能丢失 |
| 游客门槛 | 解释需要登录的原因，不把它伪装成网络错误 |
| 会话过期 | 清除账号数据、保留公开缓存和播放上下文，提示重新登录 |
| 内容不可播放 | 显示具体不可用状态并允许继续队列 |
| 后端地址无效 | 阻止请求风暴，直接进入网络设置修复路径 |

### 10.1 骨架屏规则

- 骨架只用于“没有可渲染内容的首次加载”。已有缓存、旧数据或恢复后的页面刷新时，继续显示内容，只增加轻量刷新指示。
- 骨架必须匹配最终页面的真实形状：首页保留欢迎区、快捷入口、横向内容区块和底部 Tab；详情页保留封面、标题、主要动作和曲目行。不能用一张通用的居中 Spinner 代替所有页面。
- App Bar、底部三个 Tab、已知的迷你播放器和返回关系属于稳定壳层，不随内容骨架消失。冷启动时尚无播放上下文，可以不显示迷你播放器。
- 每个数据区块可以独立显示和退出骨架；先返回的区块先展示，不能等待整页所有请求结束后一起揭示。
- 骨架块的宽高、圆角、列表间距和图片比例必须与最终组件一致，数据返回后不得发生明显布局跳动。
- 动画只用于帮助识别加载状态；开启“减少动态效果”时使用静态占位。真实数据已经返回时不得为了满足最短动画时长而延迟展示。
- 请求失败后，只有对应范围的骨架被替换为异常状态：整页首载失败进入页面级异常，单个区块失败进入局部异常。

### 10.2 异常承载层级

异常组件按影响范围选择承载位置，而不是按接口名称决定：

| 影响范围 | 承载方式 | 适用情况 | 必须保留的上下文 |
| --- | --- | --- | --- |
| 页面无任何可用内容 | 全屏/页面级异常 | 启动阶段后端不可达、页面首次加载失败 | App 已完成启动时保留 App Bar 和底部 Tab；提供重试，后端问题提供网络设置入口 |
| 页面部分内容不可用 | 区块内联异常 | 首页单一区块、详情附属数据、列表分页失败 | 已成功内容、滚动位置和其他可操作区块；只重试失败区域 |
| 短暂操作或播放结果 | 全局 Toast | 点赞、收藏、评论发布、播放自动跳过/停止等不改变页面结构的结果 | 当前页面和输入内容；由 App 根部唯一 Toast Host 承载，不用错误页打断用户 |
| 全局账号状态变化 | 模态 | 会话过期、账号授权失效 | 当前 route、公开缓存和仍可用的播放上下文；明确提供重新扫码与以游客继续 |

公共 HTTP 地址等可在保存前确定的错误直接显示在设置字段旁，并阻止保存；它不是“网络请求失败”，也不应跳转到通用错误页。只有没有任何有效内容可继续展示时，异常才可以占满内容区域。

### 10.3 会话过期

- 收到明确的会话失效响应后，只清除 Cookie、用户资料和账号作用域缓存；公开首页/搜索缓存、当前公开内容 route 与仍可播放的当前歌曲继续保留。
- 当前页面覆盖全局模态，主动作是“重新扫码”，次动作是“以游客继续”。选择重新扫码时保存返回目标，登录成功后回到原上下文。
- 以游客继续后，“我的”显示登录门槛，公开页面继续可用；不能把会话过期表现成普通网络失败，也不能直接把整个 App 替换成空白登录页。
- 登录页自身的二维码过期属于二维码局部状态，按 Web 同款遮罩和“刷新二维码”动作处理，不触发 Toast 或全局会话过期模态。

### 10.4 播放失败

- 播放失败不能替换成通用错误页。完整播放器仍是一张铺满屏幕的沉浸画布，保留封面/唱片、歌曲信息、进度、队列和退出路径；迷你播放器也保留当前曲目上下文。
- 对齐 Web：前两次可自动跳过失败曲目并由**顶部全局 info Toast**提示“当前歌曲播放失败，已为你切到下一首”。
- 连续失败达到阈值、或没有下一首时停止播放，保留当前歌曲/队列上下文，并由**顶部全局 error Toast**提示“连续多首歌曲播放失败，可能是网络或播放源异常，请稍后重试”。该 Toast 可以提供“重试”和（存在下一首时）“下一首”两个动作。
- Toast 是 App Shell 的 overlay，而不是 PLAYER 或迷你播放器的子组件；它固定出现在安全区顶部、覆盖当前 route、播放器或 sheet，无论用户是否离开播放页都只出现一次并按同一 ID 去重。操作按钮命令同一 Playback Module，不在播放器页面再造一条操作栏。
- 播放失败不清空队列、不退出沉浸播放页，也不能误触发账号登录门槛。

## 11. 首轮线稿实施约束

第一轮页面工作只验收以下内容：

- 所有 V1 页面都有可到达的 route 或 sheet 占位。
- 三项底部导航、My 三项内部切换、迷你播放器和详情返回关系成立。
- 普通内容详情必须保留并正确高亮底部三 Tab；沉浸层隐藏时要在页面规格和线稿标题中明确说明，不能像遗漏。
- 每个页面至少能切换“内容 / 空 / 加载 / 错误 / 登录门槛”示例状态；首页和详情不得共用同一套通用骨架。
- 首次加载失败、局部失败、会话过期和播放失败必须分别用页面级、区块、模态和**全局 Toast**展示，不能合并成一张通用错误页。
- 使用 Fake Adapter 和固定 fixture，不发真实请求、不写真实账号数据。
- 关键按钮可以导航或打开只读 sheet，但不执行收藏、评论、删除、编辑等真实 mutation。
- 字体、颜色、间距只达到可评审程度；不以像素级还原作为完成条件。
- 线稿验证后才按“信息层级 → 交互 → 数据状态 → 动效与视觉”顺序迭代。

当前 HTML 原型明确是 `PROTOTYPE — throwaway/read-only`，只用于共同阅览，不直接复制为生产 Flutter 代码。

## 12. V1 明确不做

- 手机号、密码、短信或导入 Cookie 登录。
- WebView 复用 Web 页面。
- 离线下载、离线曲库或持久音乐文件管理。
- 完整 Folia 九种视觉效果及其设置面板。
- Electron 托盘、桌面歌词窗口、窗口管理、桌面快捷键和桌面更新器。
- MV 页面。
- 歌单评论和歌单曲目服务器重排。
- 当前后端没有写接口的 Voice List 新建流程。
- 为了“看起来完整”而放置没有响应的按钮或 Tab。
